\# Planning

\## 1. 一句话定义

Planning 是 Agent 制定任务步骤、执行顺序和执行策略，并在必要时根据执行结果或环境变化调整计划的机制。





\## 2. Planning 解决什么问题？

Planning 解决复杂任务缺乏明确执行步骤和策略的问题。它负责确定任务步骤、执行顺序与策略，并在执行结果或环境变化导致原计划不再合适时调整计划。动态路由可以配合这一过程，但不等于动态规划。





\## 3. Planning 与 Agent Loop、Workflow 的区别



## 3. Planning 与 Agent Loop、Workflow 的区别

| 概念 | 核心职责 | 关键问题 |
| --- | --- | --- |
| Planning | 制定或调整任务步骤、顺序与策略 | 接下来应该做什么？ |
| Agent Loop | 组织反复决策、行动和反馈 | 如何持续运行，直到完成或停止？ |
| Workflow | 定义步骤连接、条件分支和流转规则 | 执行完这一步后，应该流向哪里？ |





\## 4. 静态计划与动态规划

静态计划： 在开始执行前确定任务步骤，执行过程中通常按照既定计划推进，不根据中途反馈重新生成计划。







动态规划： 根据新的状态、执行结果或环境反馈，重新调整任务步骤、顺序或执行策略。

\## 6. 与 LangGraph 的关系

LangGraph 不会自动替 Agent 完成规划，而是提供 State、Node、Edge 和 Conditional Edge 等机制，让开发者能够实现计划生成、计划执行、条件路由与动态调整。Planning 是系统设计中的职责，LangGraph 则提供构建该系统的执行框架





\## 7. 当前阶段的学习结论

程序运行成功不仅意味着没有语法错误，还意味着这次执行没有发生未处理的运行时异常。但它仍然不能证明计划在逻辑上合理或能实现任务目标





Agent 系统需要根据任务状态和环境反馈决定后续执行路径；如果只是选择预定义的分支，通常属于条件路由；如果需要修改原有计划的步骤、顺序或策略，则属于动态规划。
