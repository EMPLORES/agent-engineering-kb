\# Messages vs State



\## 1. Messages 和 State 分别是什么？



Messages 负责记录程序中的消息列表内容，主要用于保存对话和交互过程中产生的消息。



State 负责保存当前任务的数据状态和内容，供程序后续读取和更新。



Messages 和 State 都是 Agent 运行过程中使用的数据载体，但它们承担的职责不同。



\## 2. 实验 28：Messages vs State



对应代码：`04-labs/28\_runtime\_messages\_vs\_state.py`



在该实验中：



\- Messages 主要负责保存消息列表中的内容。

\- State 主要负责保存当前任务的数据状态和内容，例如目的地和任务状态。



Messages 和 State 在本次实验中是相互独立的两个变量。它们分别保存不同的数据，程序不会自动将 Messages 中的内容同步到 State，也不会自动建立两者之间的数据联系。



\## 3. 函数如何读取数据？



在实验中，`plan\_trip(state)` 函数通过接收 State 参数，读取其中的目的地和任务状态，并根据这些数据执行规划逻辑。



State 中的数据发生变化后，`plan\_trip(state)` 读取到的内容也会发生变化，因此规划结果可能随之改变。



但是，`plan\_trip(state)` 并没有直接读取 Messages。即使 Messages 中的内容发生变化，也不会自动影响该函数的执行结果。



这说明：程序是否能够使用某项数据，取决于函数是否读取了这项数据，而不是数据是否存在于程序中。



\## 4. 实验中的关键现象



\- 修改 State 中的数据，`plan\_trip(state)` 会读取更新后的数据，进而可能产生不同的规划结果。

\- 修改 Messages 中的数据，消息列表的内容会发生变化，但不一定影响规划结果。

\- 原因是当前实验中的 `plan\_trip(state)` 只读取 State，没有读取 Messages。



因此，Messages 中的数据不会自动影响 State，也不会自动改变读取 State 的函数的执行结果。



\## 5. 如何让 Messages 影响后续决策？



如果希望 Messages 中的信息能够影响后续规划，需要在程序中建立相应的数据读取或传递关系。



例如：



\- \*\*直接读取 Messages：\*\* 让后续函数直接读取 Messages 中的消息内容，根据消息内容执行后续逻辑。

\- \*\*更新结构化 State：\*\* 从 Messages 中提取需要的信息，再将这些信息更新到 State 中，让后续函数通过读取 State 获取更新后的任务数据。



两种方式的区别在于：第一种方式直接使用消息列表中的内容；第二种方式则是将消息中的相关信息提取出来，转化为结构化的任务状态数据。



在实际 Agent 系统和框架中，具体采用哪种方式，取决于系统的架构设计。



\## 6. Messages 和 State 的区别与联系



Messages 主要负责存储消息列表的内容，记录对话和交互过程中产生的信息。



State 主要负责存储当前任务的数据状态和内容，为程序后续执行提供需要读取和更新的数据。



Messages 和 State 都是数据载体，但数据的结构、用途，以及程序是否读取它们，决定了它们对执行行为的影响。



在 Agent 运行过程中，根据系统和框架的设计，程序可以直接读取 Messages 中的内容，也可以提取其中的信息并更新到结构化 State 中。



需要注意的是，Messages 和 State 并不一定相互独立。在一些系统和框架中，Messages 也可以作为 State 的一个字段。但在本次实验中，两者是独立定义的变量，没有自动的数据同步关系。



\## 7. 我的理解



Messages 和 State 都是数据载体，但数据的结构、用途，以及系统是否读取它们，决定了它们是否会影响程序的执行行为。



Messages 存储的是消息列表中的内容，但这些内容不一定会对当前任务的数据状态和规划结果产生影响。



State 存储的是当前任务的数据状态和内容。当程序中的函数读取 State 后，就可以根据其中的数据执行相应的逻辑。



如果希望 Messages 中的信息影响后续任务，就需要让程序直接读取 Messages，或者将其中的信息提取出来并更新到 State 中，建立两者之间的数据联系。
