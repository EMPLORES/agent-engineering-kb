\# Runtime Safety: Tool Registry, Validation and Execution Limits



\## 1. 一句话定义



Runtime Safety 是指通过工具注册、参数校验、权限控制、异常处理和执行限制等机制，约束 Agent 的运行行为，降低错误执行和资源浪费的风险。



\## 2. Tool Registry



Tool Registry 将工具名称映射到实际可调用的函数或处理器。



例如：



```python

TOOL\_REGISTRY = {

&#x20;   "divide": divide,

}

```



主要作用：



\* 根据模型提出的工具名称查找实际工具。

\* 限制通过该调用机制可以访问的工具集合。

\* 为后续权限控制和工具管理提供入口。



注意：注册表不等于完整的安全机制。已注册工具仍需要权限检查和参数校验。



\## 3. 参数校验



参数校验至少应考虑：



1\. 工具名称是否存在。

2\. 参数是否为预期的数据结构。

3\. 必填字段是否缺失。

4\. 参数类型是否正确。

5\. 参数值是否满足范围与业务约束。

6\. 调用者是否有权限执行相应操作。



以 divide(a, b) 为例：



\* {"a": 10, "b": 2}：符合基本输入要求。

\* {"a": 10}：缺少必填参数 b。

\* {"a": "hello", "b": 2}：a 的类型不符合要求。

\* {"a": 10, "b": 0}：违反除数不能为零的约束。



参数通过校验也不保证任务最终成功，执行结果仍需检查。



\## 4. 异常处理



工具执行可能失败，例如：



\* 参数错误

\* 网络超时

\* 服务不可用

\* 权限不足

\* 业务规则拒绝请求



Runtime 应将错误转化为可处理的结果，并根据错误类型决定重试、修正请求、转交人工或停止任务。



\## 5. 执行限制



常见机制包括：



\* 最大执行步数

\* 工具调用超时

\* 有限次数重试

\* Token 或费用预算

\* 权限与审批检查

\* 任务停止条件



不能无限重试所有错误。对于参数缺失、权限不足等不可通过重复请求解决的问题，通常应修正请求或停止执行。



\## 6. 三种成功状态



\* 调用已发起：Runtime 已收到并处理工具调用请求。

\* 工具执行成功：工具正常返回了结果。

\* 任务完成：结果经过必要验证，符合用户要求。



这三个状态不能混为一谈。



\## 7. 我的理解



LLM 负责提出行动请求，Runtime 负责调度和控制，Tool 负责实际执行。



安全的 Agent 不仅需要知道如何执行，还需要知道哪些操作允许执行、参数是否有效、失败后如何恢复，以及什么时候必须停止。
