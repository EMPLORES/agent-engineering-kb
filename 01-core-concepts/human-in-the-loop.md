# Human-in-the-Loop（HITL）

## 1. 一句话解释

HITL 是在 Agent 执行过程中，在需要人工判断、授权或确认的关键节点引入人类决策。例如，执行系统遇到超出当前自动执行权限的操作时，可以通过 `interrupt()` 提出输入请求，然后进行人工审批，以降低操作风险。HITL 是一种人机协作模式，目标是让 Agent 在明确的业务规则和权限约束下，与人类协同工作。

## 2. 它解决什么问题？

在真实的生产环境中，AI 进行高风险操作时，需要尽量避免错误操作，例如模型幻觉导致的错误决策、不合适的工具调用和越权行为。Agent 在生产级环境中，如果没有必要的权限限制、执行策略和审批流程，就可能出现不受控的行为。但通过权限约束、风险控制和人工审批等机制，可以让 Agent 更加可控，并与人类协同工作。

## 3. 最小工作流程

```text
Agent 发起请求
→ 判断是否需要人工审批
→ interrupt() 提出输入请求
→ LangGraph 保存可恢复的执行状态
→ 外部系统展示审批请求
→ 人工审批
→ 使用相同的 thread_id 恢复执行，将审批结果作为恢复输入
→ 根据审批结果进入执行或拒绝分支
→ 任务结束
```

注：中断处理与检查点保存由 LangGraph 的运行时及 Checkpointer 协同完成；人工审批界面通常由外部业务系统负责。

## 4. 核心机制

- `interrupt()`：负责暂停图执行，并提出外部输入请求。
- `checkpointer`：负责保存和读取图执行的检查点，为恢复执行提供必要的状态与执行元数据。
- `thread_id`：区分不同的 LangGraph 执行线程，用于定位对应的检查点和恢复状态。
- `Command(resume=...)`：向已中断的图提供恢复输入，使图继续执行。

## 5. State 与 Checkpoint 的区别

State 保存的是当前任务的状态数据内容。Checkpoint 保存的是某一时间点的图执行状态记录，通常包含 State 以及恢复执行所需的相关元数据。在使用持久化 Checkpointer 的情况下，Checkpoint 是恢复执行的重要基础。

State 本身只描述任务数据状态，不能单独保证恢复到原来的执行位置；需要结合 LangGraph 的检查点机制，才能支持中断后的恢复执行。

## 6. 实验观察与局限

### 基础人工审批实验

```text
========== 新任务 ==========
[Agent] 已准备转账请求：500 元
[Human] 正在审核转账请求
[Human] 审批通过
[System] 正在执行转账：500 元
[System] 最终状态： completed

========== 新任务 ==========
[Agent] 已准备转账请求：2000 元
[Human] 正在审核转账请求
[Human] 审批拒绝
[System] 未获得批准，不执行转账
[System] 最终状态： rejected
```

### LangGraph 中断与恢复实验

```text
========== 第一阶段：启动任务 ==========
[Agent] 已准备转账请求：500 元

========== 中断时的状态 ==========
{'amount': 500, 'approved': False, 'status': 'waiting_for_approval', '__interrupt__': [Interrupt(value={'type': 'approval_required', 'amount': 500, 'message': '是否批准转账 500 元？'}, id='18860ef7a5f695c88b22910c8a9e627e', response_schema=None)]}

========== 第二阶段：人工批准并恢复 ==========
[Agent] 收到审批结果：True
[System] 正在执行转账：500 元

========== 最终状态 ==========
{'amount': 500, 'approved': True, 'status': 'completed'}
```

### MemorySaver 的局限

`MemorySaver`（当前 LangGraph 中通常使用名称 `InMemorySaver`）是内存型 Checkpointer，负责在当前 Python 进程中保存和读取检查点。程序关闭或进程崩溃后，保存在内存中的检查点通常会丢失，因此不能保证跨进程恢复。若生产环境需要在程序重启后恢复任务，就需要使用持久化 Checkpointer，将检查点保存到数据库等持久化存储中。

## 7. 与企业生产环境的关系

此外，还需要明确审批对象与权限边界，确保审批人有权批准相应操作，并在实际执行前重新校验关键参数，防止审批后操作内容发生变化。对于超时、拒绝、重复恢复和系统异常，也需要定义明确的处理策略和审批记录与审计：记录审批请求、审批人、审批结果、时间及实际执行结果，以便事后追踪和审计。
